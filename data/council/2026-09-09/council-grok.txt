**对这组问题本身**

「已经确认的共同点（事实陈述，不是主张）」这句话是错的。四个项目各自撞上「测到的不是以为在测的」，这是**观察**；把它们收成「同一族问题 / 七族表 / 覆盖八个领域」，是**事后分类**。同一人、同一套认识论、四个自己造的工具里反复看见 construct mismatch，不是 Campbell–Fiske 意义上的 convergent validity，是一把锤子找钉子。八个领域里至少四个（博弈 testbed、行情管线、组织知识库、上市公司 KPI、二手归因）在材料里没有对应产物，表被撑大了。**置信：高。**

Q1 把「一个仓库 / 一个产品 / 一个统一实体」捆成一个「合并」——这三项成本、收益、可逆性都不同，不能当一个开关。Q4 的「只能留两个」默认稀缺单位是项目，真正稀缺的是业余小时和一次注意力。缺的关键信息：assay 的 53%→83% 的 n / 任务族 / 模型名单；四个仓库各自已投入小时和是否已有公开长文；prophetmap 的 A/B 有没有对外宣布。这些会移动 Q4，不移动 Q1 的代码层结论。

**Q1. 不合并仓库，不合并产品，也不要再建一个伞实体。四个仓库保持技术独立。但这不是「四条活产品线」。**

推理链：

声誉资产的生产函数是：**一个可被记住的主张 × 署名 × 可核验证据 × 被目标受众看见的次数**。仓库拓扑几乎不进入这个函数。读者记的是句子和数字，不是 GitHub 组织图。

合并**代码**省不下维护。提问者自述：不共享代码、技术栈不同。合并的成本是真实的（prophetmap 评分字段冻结到 2027-08-17，并进一个仓会把实验边界和发布边界搅在一起）；收益是零。monorepo 最佳实践在这里不适用。

合并**产品**直接违反约束：目标不是收入，执行者是业余一人。四个域的用户（美股投研 / LLM eval / 代币风控 / coding agent）不是同一批人，硬合成一个产品是在为不存在的用户做 roadmap。

合并成**统一实体 / 伞仓库**是第三次犯同一类错：用组织结构代替主张。材料里已经有一次伞实验（agent-tool-interop）。我**不用**那条 14 天 traffic 当「伞失败」的因果证据——见 Q3。拒绝再建伞的理由是：第五个要维护的命名空间，对业余时间是净负债；而且把四个域装进一个牌子，会把「跨域独立出现」做成「我自己的框架自洽」。后者对论证是降级，不是升级。若它们真是独立复现，就更不该合成一个产物。

「保持独立」若被理解成四个都继续工程迭代，同样错。一人业余养四条活线，结果是四份半成品、零篇能被引用的长文。正确形态是：**仓库法律上独立；时间上最多一条在产证据，其余维护或冻结；主张只在公开发布里统一。**

**置信：高**（代码/产品不合并）；**中**（「不要第五个伞」——若你已有稳定读者群、伞只是一个索引页且零维护，伤害很小，但材料里看不到这个读者群）。

**Q2. 「整合」的正确单位不是代码，也不是含糊的「叙事」。是：一句可证伪主张 + 发布队列。**

依据：声誉的可交易物是**别人能转述的那句话**和**指向证据的链接**。四个仓库已经是证据生成器，不是分发器。

可操作的整合只有三层，从硬到软：

1. **主张（必须有）**：一句。例如「分数分歧首先是构念/量表没对齐，不是模型个性或 vendor 谁更准」。bio、置顶、每篇长文首段，同一句。这不是品牌故事，是假设。
2. **发布队列（必须有）**：业余时间同一窗口只产出**一个**公开物（一篇英文长文，或一个可跑的 repo 版本）。文中以一个项目做主证，另外的当复现/对照。四次分别介绍四个项目 = 没有整合。
3. **受众（结果，不是手段）**：你不能先「整合受众」。投研读者和 eval 读者不会因为你声明他们是一类人就变成一类人。若主张成立，重叠会出现在「关心这个数字是否测了它声称的东西」的人里；那是事后观察，不能当事先策略。

明确排除：共享库、统一 CI、统一产品名、统一 changelog。没有共同代码，这些是仪式。

「叙事」这个词本身没有验收条件，不能当整合单位——否则 Q5 的决定事先不可证伪。主张有证伪条件（新域里补齐构念定义后，分歧不下降），发布队列有计数（90 天公开物是 0 还是 1）。

**置信：高。**

**Q3. 这条 traffic 几乎只能描述「那 14 天没人来」；不能为合并/独立提供因果结论。**

**能支持（弱描述）：**

- 在被查看的那 14 天里，该仓库没有获得可辨识的外部发现。`unique visitors = 1` 与作者本人打开高度相容；`views = 6` 量级也相容。
- 「把仓库建出来」本身不会产生分发。GitHub 对未推广、无 topic、无入站链接的新仓，零流量是默认值，不是异常值。
- `topics` 为空是**分发卫生缺陷**，应记为干预缺失，不能当结果。

**不能支持：**

- 「伞这种组织方式导致没人看」——无对照（同期一个非伞、同样零推广的仓流量未知），无干预日志（发过 X 没有、README 质量、是否提交到 Awesome 列表、是否挂在长文里）。`topics` 空已经把「没做分发」写进了同一条证据。
- 内容质量低、主张无价值、另外三个项目也会是零。
- 14 天是检验窗口。无推广的公开仓，14 天的期望流量本来就接近零；这测的是发现率的地板，不是组织形态。
- 因此也**不能**支持「所以不要合并」或「所以保持独立」。把 n=1、无对照、干预缺失的流量当成架构判决，本身就是构念用错：你以为在测「伞是否为正确的整合单位」，实际在测「一个没做分发的新仓有没有魔法流量」。

证据强度：对「未推广新仓无流量」是重复确认常识；对 Q1 的决策是**零**。**置信：高。**

**Q4. 边际声誉价值：assay ≫ prophetmap（仅作冻结实验+写作）> decision-confidence 的 finding（不是其工程）> agent-tool-interop 作为活仓库。只能留两个：留 assay 与 prophetmap；砍掉的是后两者的工程生命，不是把 finding 扔掉。**

排序标准（按你的目标，不是按已投入）：`英文受众规模 × 主张的可引用性 × 公开可核验 × 每业余小时能产的新证据`。私有仓对 GitHub 声誉贡献为零。

1. **assay**（暂排第一，**置信：中**）。53%→83% 是四个里最像「别人会转述的数字」的东西，且落在 LLM-as-judge 这个正在被实验室和工程团队争论的场。GitHub 形态天然（可跑的 testbed）。但材料没给 n、任务族、模型集；若这是单任务族小样本，「补一句外推规则」可能只测了「模型会不会遵守刚写上的规则」，不是「分歧的主因是 rubric」。没有 holdout 任务族之前，这个第一名是暂定。

2. **prophetmap**（第二，但是**维护冻结实验，不是继续做产品**）。它是唯一自带外部时钟、预注册、已知缺陷清单的东西。这类资产稀缺，杀它等于扔掉一个已经在走的一年窗。它拿不到 GitHub 声誉（私有），「AI 供应链地图」这个体裁在英文圈已经很挤，差异化在方法纪律不在图层数。每日/周/月审计是四项里最贵的固定成本，所以工程上只保审计与冻结，不修那 19 个「刻意不修」。公开价值几乎全在未来那篇方法/A/B 长文。A/B 若从未对外宣布，中止的声誉成本接近零——这一点材料没说，**不确定**。

3. **decision-confidence**：5 分对 100 分、两边都对，是主张里最好用的**例子**，不是最好的活项目。适配更多 vendor 是维护跑步机，受众（代币风控）也不是「英文长文 + GitHub」里地位最高的那群。finding 写进长文即可；MCP 已经存在的话，当 demo 挂链接，不要当主线。

4. **agent-tool-interop 活仓库**：15 条纪律挂事故，本质是一篇方法文的骨架，不是别人 clone 了能跑出数字的东西。coding agent tool-use 赛道会被实验室和框架项目碾压。把 15 条收进长文；仓库降为附录。它当伞失败，不是因为它是伞，是因为没有主张、没有分发、没有可跑物——见 Q3。

**砍掉哪两个：** 砍 decision-confidence 和 agent-tool-interop 的**持续工程**。不是删 finding，不是必须删仓库。archive 或 README 指向长文即可。

不选「interop + prophetmap」当双活线：那是文档最厚、沉没成本最高的两个，不是目标受众会付钱（注意力）的两个。不选双 eval（assay + decision-confidence）：丢掉唯一带一年期预注册时钟的资产，而且两个 finding 在主张层高度同构，边际证据重复。

若 90 天内 assay 的 53→83 经不起 holdout，第一名让给 prophetmap 的方法长文，assay 降为引用。**这是预先写明的翻转条件。**

**Q5. 「四仓独立、只统一对外叙事」最可能死在：叙事没有生产函数，业余时间仍按四个工程任务分配，于是「统一」从未发生。**

不是「读者看到四个 repo 会认知过载」——大多数人根本看不到四个 repo。也不是「叙事无法测量所以注定失败」；主张和发布队列可以测，只是如果你把整合单位定义成「叙事」，你就故意选了一个不可测的量。

**可观测失败信号（满足任一条，就判这个决定错了）：**

- **过程失败（90 天）：** 不存在一篇（或一条长帖）同时满足：标题或首段出现那句主张，并且作为证据引用了 ≥2 个项目；与此同时，四个仓库中 ≥3 个仍有非琐碎工程提交。这表示你执行的是「四仓独立」，从未执行「统一对外」。
- **市场失败（在上一篇已经发出的前提下）：** 该文带来的可清点互动（星标、转发、引用、认真评论）全部落在单一域产品上（只讨论股票图层，或只讨论 judge 百分比），连续 2 篇都没有人复述那句主张。这说明受众买的是展品，不是构念框架；这时继续「统一叙事」是在伤害那个真正有需求的展品，应停掉统一、加码那个展品。

两条都要：只看过程，会把「没写」和「写了没人要」混在一起——又一次测 Y 当测 X。

**置信：中高**（过程失败是业余一人的基线结局）；市场失败那条要等第一篇真正发出，发出前是未鉴定。
